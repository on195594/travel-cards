## 响应式与交互

- 攻略卡片桌面三列，1020px 及以下两列，540px 及以下一列；760px 及以下搜索控件纵向排列。
- 编辑器在 1020px 及以下单列，预览取消 sticky 限高；760px 及以下表单字段单列。
- 图片使用原生 img（支持管理员配置的图片域名）与 async decoding；首页第一张卡片使用 eager / high priority，其余 lazy；无封面卡片显示目的地。详情封面预留 16:9、手机 4:3 的展示区域，contain 保留完整图片，提供原图链接。
- 搜索清空后焦点返回输入框；卡片由单一链接提供点击与键盘入口。保持跳过导航链接与焦点轮廓。
- `prefers-reduced-motion: reduce` 下关闭平滑滚动、卡片位移与图片缩放，按钮（包括主题和清空按钮）不缩放；颜色／边框反馈仍可保留。
- 右下角悬浮主题按钮仍可能遮挡部分正文，属于已记录的未解决问题，见 UI 审查报告。

## OAuth 管理页面（2026-10-10）

- `/admin/oauth/consent`：显示未验证客户端名称、精确回调和批准 scopes，管理员原生表单显式同意/拒绝；过期或重复确认提供重新连接提示。
- `/admin/oauth`：显示已授权/已撤销客户端及注册到期时间，提供原生表单撤销。攻略管理页仅在 OAuth 开关启用时显示入口。
- 登录页新增仅允许恢复本站 authorize/consent 的 returnTo；不接受外部跳转。
- 新页面沿用现有 panel/login/admin/actions 样式与主题；只补管理员列表中 form 不缩窄的共享规则，避免手机视口的撤销按钮逐字换行。不重做视觉系统。
- 页面 metadata 使用 `same-origin` referrer，防止原生表单 POST 的 Origin 变成 `null`；外部回调响应仍使用 `no-referrer`。服务器仍严格拒绝缺失或 `null` Origin。
- 浏览器视觉检查使用隔离 MongoDB、合成管理员 Session、本地 production server；模拟 1440×1000 与 390×844，覆盖明暗主题和 reduced-motion。视觉检查两轮，授权/撤销原生表单另做功能验证；不是实际手机、读屏或 Gemini 客户端验收。临时截图/Session 不提交。

## 性能变更复审（2026-10-10）

- 范围：上一轮图片预连接、Mongoose 初始化缓存、URL 去重及卡片离屏渲染；未重新审查 MCP/OAuth，未部署本轮修复。
- 删除额外 `initPromise`：当前 Mongoose `Model.init()` 在 `this.$init` 非空时直接返回已有 Promise，应用层缓存没有避免额外数据库查询，亦无测量证明收益。
- 撤回 `.card` 的 `content-visibility: auto` 与固定 380px 估算：卡片高度随内容与视口变化，估算会使长列表滚动时页面高度变化。40 张高卡片的合成复现中，旧规则导致总高度增长 1620px；修复后用实际全局样式测试，滚动前后均为 26080px。该测试不代表线上 CLS 分数。
- `getImageOrigin()` 复用已有安全 HTTPS URL 校验；缺失、非法协议、凭证、查询与片段配置不输出预连接提示。新增 8 项环境测试。
- 保留 `syncUrl` 查询去重与图片域名预连接。预连接是浏览器提示而非保证；撤回此前“节省 150–400ms”的无测量依据结论，也不宣称提升并发性能。
- 本轮验证：277 项测试、lint、production build、Compose 配置及 `git diff --check` 通过；新增 `checkCardScrollStability(page, css)` 浏览器回归通过。
- 未重跑完整站点交互矩阵、真实设备或线上 LCP；此前浏览器验证记录只适用于对应轮次。

### 浏览器审查（2026-10-23）

使用本地 production build、隔离 MongoDB、合成攻略与合成账号。以下记录审查复现和同日获用户授权后的修复，均为本地验证，尚未上线。

- 首页/详情的 320、390、768、1440px × 明暗主题共 16 项横向溢出检查通过；后台新建页的 390/1440px 检查通过。搜索防抖与取消、日期锚点、封面展示、复制公开链接、主题持久化、reduced-motion 下关闭平滑滚动、账号密码登录与退出均通过；没有浏览器 pageerror。
- **编辑内容保护已修复**：原先缩短天数和返回列表会无提示丢失输入。现在天数输入结束后才处理删减，删除已填写的行程需确认，取消保留原内容；从 2 天键入 12 天不会因中间数字误删。编辑器进出使用普通页面导航，`beforeunload` 覆盖返回列表、浏览器后退和刷新；未保存时取消离开能保留表单，保存后不再误拦截。
- **保存期间输入丢失已修复**：补测发现首次保存的路由替换会重建编辑器，覆盖响应期间新输入。现在首次保存只更新历史 URL，保持编辑器实例，使用返回快照合并字段；POST 和 PATCH 响应期间继续输入的文字均保留，并仍显示“有未保存的修改”。发布/撤回使用返回状态更新界面，避免额外刷新重建。
- **错误提示已修复**：原先 400 的“请求数据无效”被显示为绿色成功消息，且具体字段丢失。现在按明确成功/失败状态展示；服务端 `issues` 显示章节、天数和字段，错误摘要可聚焦并通过 `role="alert"` 通知。只填标题后保存的三个行程字段错误均可见，输入保留，服务端校验未放宽。
- **来源时间已修复**：`datetime-local` 现在按浏览器本地时间显示，仍以 UTC ISO 提交；hydration 时不使用服务端时区冒充用户时区。Asia/Shanghai 的 08:00→08:01、America/Los_Angeles 的前一日 17:00→17:01 均正确保存为 `2026-10-23T00:01:00.000Z`，刷新后显示不跳变；空值和无效值不会触发日期转换异常。
- **搜索故障反馈已修复**：查询中、失败和成功后无结果分别展示；503 会说明失败并提供“重新搜索”，保留卡片时注明仅来自已加载攻略。手动重试可恢复；实际无匹配仍显示空结果；清空和切换关键词会取消旧请求，延迟旧响应不能覆盖新结果。
- 浏览器回归脚本：`scripts/check-public-ui.mjs`、`scripts/check-editor-ui.mjs`。修复后验证了上述行为、后台 390/1440px × 明暗主题、公开页原有 16 项布局检查，并完成编辑错误和搜索失败的桌面/手机视口截图核对；无 pageerror。未创建自动保存或本地草稿存储，离开提醒依赖浏览器的原生确认机制。
- Impeccable detector 返回 1 项 `side-tab` 告警，指向 `globals.css` 的时间线竖线。结合行程语义和页面核对，保留该时间线，不作为缺陷。未做全量色彩对比、读屏、真实手机或线上性能验收。
